# 门店会员储值与积分台账助手｜用户说明书

## 一、适用场景

适合小型零售店、餐饮店、美容美发、洗护、维修和社区服务门店，记录会员资料、储值余额、消费、退款和积分变化。适合单店或由一台电脑维护的轻量会员台账。

本工具是本地记录软件，不是支付系统。它不会连接微信、支付宝、银行卡、POS、收银 SaaS 或任何平台；实际收款、退款必须先通过门店已经开通的合规渠道完成，再由店员把结果录入本软件。

## 二、首次使用

1. 双击 `MainlandStoreMembershipLedger.exe`。
2. 首次启动会显示本机设备码；取得卖家提供的本产品授权文件后，按提示放入本机授权目录。
3. 数据默认保存在当前 Windows 用户的 `%LOCALAPPDATA%\MainlandBusinessTools\store-membership-ledger.json`。
4. 建议先用测试会员练习充值、消费、退款、积分兑换和备份恢复，再录入真实资料。

## 三、会员资料

- 点击“新增会员”，填写姓名、联系电话和备注。
- 会员编号由软件自动生成；CSV 导入时也可提供自己的编号，但不得与本机已有编号重复。
- 可切换会员“正常/停用”状态。停用会员不能办理新的充值、消费、退款或积分兑换；历史资料和流水保留。
- 不建议录入身份证号、银行卡号、支付密码等不必要的敏感信息。

## 四、储值与交易规则

- **充值：**先在门店实际收款，再记录充值金额。软件只增加本地储值余额，不会发起支付。
- **消费：**录入实际消费金额。余额不足时拒绝记账，不允许余额变成负数。
- **退款：**必须关联同一会员此前的一笔消费流水；累计退款不能超过原消费金额。部分退款会按累计退款比例冲回该笔消费已获得的积分，最后一次全额退款会冲回剩余积分。
- **积分：**每消费满 1 元获得 1 分，不足 1 元部分不计分。积分兑换只扣减积分，不自动抵扣现金，也不会生成支付或优惠券。
- 交易流水为追加式记录，不能在软件中直接编辑或删除。发现录入错误时，应按门店实际处理流程补录相应交易，并在备注中说明；不要直接修改 JSON 文件。

## 五、导入、导出和报表

- “导入会员 CSV”只导入会员资料，要求 UTF-8/UTF-8 BOM 且表头与软件模板完全一致。
- 导入采用整批校验：任何一行无效、会员编号重复或与本机编号冲突，整批都不会写入。
- “导出会员”导出会员资料；“导出交易流水”导出逐笔交易；“导出余额报表”按交易流水重新计算会员储值和积分余额。
- CSV 导出使用 UTF-8 BOM，兼容常见表格软件，并对以 `=`、`+`、`-`、`@` 开头的文本进行公式注入防护。
- 不要把导出的会员资料随意发送给他人；联系电话等个人信息应按门店隐私管理要求保存。

## 六、备份与恢复

1. 点击“备份”，选择安全位置保存 JSON 备份。
2. 建议每日营业结束后备份，并把备份复制到受控的 U 盘或门店自有加密存储介质。
3. 点击“恢复”会替换当前会员及交易数据；恢复前应先备份当前文件。
4. 备份包含 SHA256 完整性摘要、交易流水和操作日志。恢复时会验证文件摘要、交易余额快照和日志哈希链；校验失败不会覆盖当前数据。
5. 不要在软件运行时用其他程序手工编辑数据文件。

## 七、操作日志和核对

- 点击“校验日志”可检查本地操作日志的 SHA256 链。
- 储值余额由充值、消费和退款流水逐笔重算；积分由消费、退款和积分兑换流水重算。
- 每日营业结束后，建议将本软件余额报表与门店真实收银/支付渠道记录逐项核对。软件不会自动取得支付平台流水。

## 八、重要限制

- 本软件不处理真实资金，不构成支付、预付卡发行、会计、税务或法律合规系统。
- 储值余额是本地台账中的待履约金额，不代表银行账户余额或已经核实的实际资金。
- 积分规则固定为“消费每满 1 元 1 分”；本版本不支持自定义倍率、积分过期、跨门店共享或自动优惠抵扣。
- 不支持导入交易流水，避免外部 CSV 直接伪造历史财务记录；历史交易通过本软件逐笔录入。
- 软件离线运行，不依赖 VPN、ChatGPT、外部 AI、云端账号或平台 API。
- 正式经营前请用本店实际规则核对储值、退款和积分政策，并妥善保护会员个人信息。
