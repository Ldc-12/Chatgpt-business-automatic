# 门店收货验收与差异处理助手｜用户说明书

## 一、产品用途

用于小型门店、便利店、餐饮店和工作室登记采购到货，核对订购数量与实收数量，记录短缺、超收、破损、拒收及供应商处理结果。适合收货现场和后续对账使用，不连接供应商或采购平台。

## 二、核心计算口径

- 短缺数量 = max（订购数量 − 实收数量，0）
- 超收数量 = max（实收数量 − 订购数量，0）
- 验收合格数量 = max（min（实收数量，订购数量） − 破损数量 − 拒收数量，0）
- 验收金额 = 验收合格数量 × 采购单价
- 差异金额 =（短缺数量 + 超收数量 + 破损数量 + 拒收数量）× 采购单价

**重要：**超收数量默认不计入验收合格数量和应付金额，避免未经确认就把多送货物计入付款。若双方确认接受超收，应先按实际采购单据修正订购数量，再重新验收。

破损数量和拒收数量均属于实收数量的一部分，两者之和不能超过实收数量。存在短缺、超收、破损或拒收时必须填写差异原因。

## 三、首次使用

1. 双击 MainlandStoreReceivingDiscrepancy.exe。
2. 首次运行按设备码提示完成本产品授权。
3. 点击“新增收货明细”，填写收货单号、采购单号、供应商、到货日期、SKU、商品名称、订购数量、实收数量、破损/拒收数量和采购单价。
4. 同一收货单可以登记多条商品明细；同一收货单号的采购单号、供应商、到货日期和经办人必须一致。
5. 有差异时填写原因，并在后续处理后将状态更新为“已补发”“已折让”“已退款”或“已关闭”。

## 四、CSV 导入导出

- 导入必须使用本软件导出的 CSV 模板，表头必须完全一致。
- 每条明细编号必须唯一；导入会先校验全部数据，任何一行有错误或重复编号，整批导入都会取消。
- 日期使用 YYYY-MM-DD，不能晚于今天；数量和金额必须为有限非负数字。
- “导出全部 CSV”用于迁移/留档；“导出差异报告”只导出短缺、超收、破损或拒收明细。
- “导出供应商汇总”按供应商汇总全部历史收货单数、明细数、差异数量、验收金额、全部差异金额及仍待处理的差异金额；已处理差异仍计入差异金额，但不会计入待处理差异金额。该导出保留原有 CSV 表头，方便继续使用旧表格和自动化模板。
- “导出期间供应商汇总”按到货日期筛选，默认填入本月 1 日至今天；可修改起止日期，留空表示该侧不限。起止日期均包含在统计范围内，开始日期晚于结束日期或日期格式错误时会拒绝导出。
- “导出供应商 SKU 差异分析”按供应商和 SKU（忽略大小写）分组，统计收货单数、发生差异的收货单数及占比、差异明细数、待处理数量、短缺/超收/破损/拒收数量、验收金额和差异金额；同一 SKU 出现不同商品名称时会标记“商品名称不一致”。占比按不同收货单计算，不按明细行计算；结果优先按待处理差异金额、全部差异金额排序，便于定位反复出现问题的供应商与 SKU。该分析同样支持到货日期起止筛选，留空表示不限，并在 CSV 中记录统计期间。 导出前可选择“仅待处理”或“全部组合”；仅待处理按待处理明细条数筛选，不按待处理金额筛选，因此即使采购单价为 0 的差异也不会被漏掉。文件名会标明筛选范围，CSV 原有表头保持不变。
- 期间汇总 CSV 使用独立表头，并额外记录“统计开始日期”和“统计结束日期”（不限时显示“不限”），方便日后核对报表口径；没有匹配记录时会导出仅含表头的 CSV。
- 导出使用 UTF-8 BOM，并对以 =、+、-、@ 开头的文本做公式注入防护。请勿自行修改表头。

## 五、备份与恢复

- 点击“备份”保存 JSON 文件，软件显示备份文件 SHA256。
- 点击“恢复”选择备份文件；恢复会替换当前全部收货明细，请先确认已有备份。
- 本地台账和备份均带 SHA256 完整性校验，损坏或被修改的文件会被拒绝。
- 默认数据路径：%LOCALAPPDATA%\MainlandBusinessTools\store-receiving.json。

## 六、重要限制

- 本工具只记录人工录入的收货和验收信息，不自动读取采购订单、不连接 ERP/POS/供应商、不自动更新库存或应付账款，也不自动付款。
- 验收金额和差异金额是按录入数量、单价计算的管理参考；最终结算以双方确认的采购单据、退补货凭证和财务对账为准。
- 建议在正式使用前先用测试数据验证新增、修改、导入、导出、备份和恢复，再录入真实业务数据。
- 所有数据保存在本机，请定期将备份复制到另一块安全存储介质。
